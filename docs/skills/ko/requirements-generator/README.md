# Requirements & Constraints Generator Skill

제품/서비스 소개 문서를 분석하여 구조화된 요구사항 정의서와 제약사항 문서를 자동 생성하는 스킬입니다.

## 언제 사용하나요?

제품 Brief, 기능정의서, 워크숍 슬라이드 요약 등 소스 문서가 있고, 이를 기반으로:
- 소프트웨어 요구사항 정의서를 만들고 싶을 때
- 제약사항 문서를 만들고 싶을 때
- 둘 다 한번에 만들고 싶을 때

## 사용 방법

### 요구사항 정의서 생성

```
이 PDF를 분석해서 요구사항 정의서 만들어줘
```

### 제약사항 문서 생성

```
제품 소개서 기반으로 제약사항 문서 작성해줘
```

### 둘 다 생성

```
이 문서에서 requirements랑 constraints 문서 둘 다 만들어줘
```

## 지원하는 소스 문서 형식

- PDF
- 마크다운
- 이미지 (슬라이드 캡처 등)
- 기타 텍스트 기반 문서

## 출력 파일

- 요구사항: `{프로젝트약어}_requirements.md`
- 제약사항: `{프로젝트약어}_constraints.md`

## 핵심 원칙

- 소스 문서에 명시된 정보만으로 도출 — 추측하지 않음
- 확인할 수 없는 항목은 "정보 부족"으로 표시
- 문서 말미에 정보 부족 항목 요약 테이블 제공
- 소스 문서의 언어를 따름 (기술 용어는 영문 유지)

## 요구사항 ID 체계

| 유형 | 형식 | 예시 |
|------|------|------|
| 기능 요구사항 | `FR-{영역약어}-{순번}` | FR-CON-001, FR-MON-002 |
| 비기능 요구사항 | `NFR-{순번}` | NFR-001 |
| 이력 저장 | `FR-HIST-{순번}` | FR-HIST-001 |

## 제약사항 카테고리

| 카테고리 | 접두사 | 예시 |
|---------|--------|------|
| 플랫폼/디바이스 | PC | PC-001 |
| 기술적 제약 | TC | TC-001 |
| 비즈니스 제약 | BC | BC-001 |
| 법적/규제 제약 | LC | LC-001 |
| 미확정 사항 | PD | PD-001 |
| 가정사항 | AS | AS-001 |
