# 요구사항 정의서 템플릿

이 문서는 요구사항 정의서의 표준 구조를 정의한다. 소스 문서를 분석하여 각 섹션을 채운다.

---

## 문서 구조

```
# {프로젝트명} 소프트웨어 요구사항 정의서

| 항목 | 내용 |
|------|------|
| 프로젝트명 | {프로젝트명} |
| 버전 | v1.0 |
| 작성일 | YYYY-MM-DD |
| 상태 | 초안 (Draft) |
| 근거 자료 | {소스 문서 목록} |
```

---

## 1. 소개

### 1.1 목적
본 문서는 {프로젝트명}의 소프트웨어 요구사항을 정의한다.

### 1.2 제품 정의
소스 문서에서 제품/서비스의 핵심 가치와 비전을 추출하여 기술한다.

핵심 가치 테이블:

| # | 가치 | 설명 |
|---|------|------|
| 1 | {가치명} | {설명} |

### 1.3 범위
소스 문서의 모듈/기능 구조에서 주요 기능 영역을 나열한다.

### 1.4 정의 및 약어
소스 문서에 등장하는 약어와 전문 용어를 정리한다.

| 약어 | 정의 |
|------|------|
| {약어} | {정의} |

---

## 2. 전체 설명

### 2.1 제품 관점
시스템 구성도를 코드 블록으로 표현한다. 소스 문서의 아키텍처 다이어그램을 텍스트로 변환한다.

### 2.2 사용자 특성

| 사용자 | 설명 | 비고 |
|--------|------|------|
| {사용자 유형} | {역할 설명} | {연령, 권한 등} |

### 2.3 사용자/회원 유형별 기능 매트릭스
소스 문서에 사용자 유형별 기능 권한이 있으면 매트릭스로 정리한다. 없으면 "정보 부족"으로 표기.

### 2.4 도메인 구조
소스 문서의 도메인 고유 체계(레벨, 카테고리, 데이터 분류 등)를 테이블로 정리한다.

### 2.5 콘텐츠/커리큘럼 구성 체계
해당되는 경우에만 작성. 운영 흐름을 코드 블록 트리로 표현한다. 해당 없으면 "해당 없음"으로 표기.

### 2.6 AI/외부 연동 개요
AI 기능이나 외부 API 연동이 있으면 정리한다. 없으면 "정보 부족" 또는 "해당 없음"으로 표기.

---

## 3. 기능 요구사항

소스 문서의 모듈/기능 구조를 그대로 반영하여 섹션을 나눈다.

### 3.N {기능 영역}

| ID | 요구사항 | 우선순위 | 근거 |
|----|---------|---------|------|
| FR-{영역}-001 | {요구사항 상세} | Must/Should/Could | {소스 문서 내 출처} |

### ID 규칙
- `FR-{영역약어}-{순번 3자리}`: 영역약어는 3~5자 영문 대문자
- 영역약어 예시: CON(Connector), CDM(Cloud Document Management), MON(Monitoring), SCHED(Scheduling), DLQ, TRAN(Transport), SEC(Security), INF(Infrastructure), EXT(Extension), BLK(Bulk), MODE, DATA, JOB

### 이력 저장 섹션
기능 요구사항에서 파생되는 데이터 저장/조회 요구사항을 통합 정리한다.

| ID | 요구사항 | 우선순위 | 근거 |
|----|---------|---------|------|
| FR-HIST-001 | {저장 항목, 저장 시점, 상태값} | Must | {관련 FR-ID} |
