# 제약사항 문서 템플릿

이 문서는 제약사항 문서의 표준 구조를 정의한다. 소스 문서를 분석하여 각 섹션을 채운다.

---

## 문서 구조

```
# {프로젝트명} 프로젝트 제약사항

| 항목 | 내용 |
|------|------|
| 프로젝트명 | {프로젝트명} |
| 버전 | v1.0 |
| 작성일 | YYYY-MM-DD |
| 상태 | 초안 (Draft) |
| 근거 자료 | {소스 문서 목록, 요구사항 정의서} |
```

---

## 1. 개요
본 문서는 {프로젝트명} 프로젝트의 제약사항(Constraints)을 정의한다.

---

## 2~9. 제약사항 카테고리

각 카테고리는 동일한 테이블 구조를 사용한다:

| ID | 제약사항 | 근거 | 영향 |
|----|---------|------|------|
| {접두사}-001 | {제약사항 설명} | {소스 문서 내 출처} | {개발/운영 영향} |

### 카테고리별 접두사 및 도출 관점

| 섹션 | 카테고리 | 접두사 | 도출 관점 |
|------|---------|--------|----------|
| 2 | 플랫폼/디바이스 | PC | 대상 플랫폼, OS, 디바이스, 프로토콜, 기존 시스템 호환 |
| 3 | 기술적 제약 | TC | 데이터 저장 방식, API 제한(페이로드/타임아웃), 외부 라이브러리, 실시간 동기화, 보안/DRM, 렌더링 엔진 |
| 4 | 비즈니스 제약 | BC | 도메인 구조 고정, 회원 유형별 분기, 비용 기준, 기능 범위 제한, 외부 API 의존, 승급/수료 조건 |
| 5 | 콘텐츠 제약 | CC | 데이터 포맷 고정, 소스/대상 제한, 마이그레이션 대상, AI 적용 범위 |
| 6 | 운영 제약 | OC | 스케줄링, 모니터링, 교육, 설정 관리, 보상 상한, 인증 정책 |
| 7 | 법적/규제 제약 | LC | 암호화 필수, 데이터 보관/삭제, 개인정보보호, 권한 동의, 이용약관 |
| 8 | 일정/리소스 제약 | SC | 구축 기간, 투입 인력, 마일스톤, 외부 의존 일정 |
| 9 | 데이터/연동 제약 | DC | 외부 시스템 연동, 키 구조/스키마, 배치 집계, 정합성, 연쇄 변경 |

소스 문서에서 해당 카테고리에 해당하는 내용이 없으면 해당 섹션을 생략한다.

## 10. 미확정 사항 (Pending Decisions)

소스 문서에서 상세 스펙이 없는 항목을 도출한다.

| ID | 미확정 사항 | 담당 | 영향 범위 |
|----|-----------|------|----------|
| PD-001 | {미확정 사항 설명} | {담당 팀 추정} | {영향받는 기능} |

도출 기준:
- 요구사항/제약사항에서 "정보 부족"으로 표기된 항목
- 소스 문서에서 "확정 필요", "추후 결정", "TBD" 등으로 표기된 항목
- 아키텍처에서 유추는 가능하나 명시적 스펙이 없는 항목

---

## 11. 가정사항 (Assumptions)

시스템이 정상 동작하기 위한 전제 조건을 도출한다.

| ID | 가정사항 | 검증 기준 | 미충족 시 영향 |
|----|---------|----------|---------------|
| AS-001 | {가정사항 설명} | {검증 방법/기준} | {미충족 시 영향} |

도출 기준:
- 외부 시스템/API 가용성 전제
- 인프라/네트워크 접근 가능 전제
- 성능/용량 기준 내 운영 전제
- 사전 준비 사항 (환경 설정, 권한 확보 등)
